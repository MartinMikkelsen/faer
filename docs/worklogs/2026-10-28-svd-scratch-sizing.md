# Divide-and-conquer SVD scratch sizing (#73)

## Decisions

- Correct the shared scratch query rather than pad the public call's buffer or change the numerical algorithm. The old query does not model the six aligned secular-merge column temporaries or establish that each recursively halved byte buffer can hold a child.
- Model the live deflation, secular-merge and output-update phases explicitly. Each merge retains two index arrays and its Jacobi coefficients; deflation, the merge's scalar/vector temporaries, and output updates have separate peak requirements.
- Bound recursion by two copies of the largest child's unaligned byte requirement. The implementation splits bytes in half without aligning the second half, so an aligned-layout size alone is insufficient. Mirror the solver's `k = n / 2` and `rem = n - k - 1` formulas and query `max(k, rem)`. Model the QR leaf's single matrix once rather than retaining its old double reservation; the resulting leaf/merge bounds grow with dimension, so the larger child covers both sides even at a fallback boundary. Only that child is queried, keeping query computation logarithmic in the dimension.
- Leave scalar arithmetic, dispatch thresholds, output-mode choices and the parallel schedule unchanged. The focused regression uses the exact public query, native f32/c32/f64/c64 inputs, the known rank-one spectrum and V orthogonality.
- Retain bounded direct-solver coverage in ordinary tests, including exact aligned layouts and odd-address slices of exactly the unaligned requirement. Direct calls start at n=1 because the private QR leaf indexes the last subdiagonal entry; empty public calls remain covered by the public tests and scan. Rank-one and nonzero bidiagonal inputs exercise deflated and nondeflated merges without external fixtures.
- Blast radius is SVD: dense SVD and public bidiagonal SVD, including the four native scalar types and omitted/vector-producing modes. The EVD module has a separate scratch query and is unaffected. Before merge, any required campaign acceptance belongs to the SVD families in faer-benchmark, with its declared shapes/dtypes/orders/budgets and collateral controls.

## Verification conclusions and constraints

- Baseline measured: fork main `2592bad8cef0bbba00d1ae31c0442ea6cf3c5310`. The focused regression fails before the correction with the reported two-usize allocation panic and passes with the correction. For the issue's 8x8 V-only call, the public query changes from 3,968 to 4,288 bytes for f32 and from 5,376 to 5,696 bytes for c32 on this host.
- All 4,800 sequential exact-query boundary calls return success and finite requested outputs: four scalar types, dimensions 0 through 257 around recursion splits, twelve fallback thresholds including values below the clamped minimum, and all four U/V presence combinations. This scratch-focused scan checks allocation sufficiency and finiteness; the focused regression also checks the known spectrum and V orthogonality. Its archived reproduction contains only the scratch scan.
- The new ordinary internal tests pass 10,080 sequential calls (n=1..70, thresholds 4/5/8, all three MatU variants, V present/absent, f32/f64, two fixtures and two alignments), plus 264 Full+V calls in a two-thread rayon pool at eleven boundary sizes. They check the rank-one spectrum, Frobenius norm and factor orthogonality where applicable. The sequential test fails with the original query while allocating a secular-merge column temporary; both tests pass with the correction, taking 1.16 seconds together locally.
- The SVD test selection, including ignored LAPACK groups, reports 77 passes and one existing failure. All 18,172 configured LAPACK SVD calls complete without call failures; the remaining three f32 V-orthogonality diagnostics are tracked separately in #75. Guarded views, buffer reuse and parallel SVD paths pass.
- The ordinary workspace library run reports 462 faer passes, 138 ignored tests and the same three strict-triangle matmul failures present on the baseline. The initial candidate's 25 public integration tests, 60 documentation tests and standard-library-only build pass; those checks were not repeated for the equivalent `max(k, rem)`/parameter-name cleanup and added tests. No unrelated test tolerance or production code is changed.
- Local checks use Rust 1.98.1 on aarch64-apple-darwin. Stable rustfmt reports the same three pre-existing formatting differences on baseline and candidate; the changed blocks introduce no additional formatting differences. Detailed logs, reproduction source and the measured source diff are in the [evidence archive](evidence/2026-10-28-svd-scratch-sizing.tar.gz).
- No upstream checkout was measured; no authorship inference or upstream feedback is part of this change.
- This is not an adopted or released change. No performance claim is made. Merge-time campaign acceptance remains pending, as do the previously documented unrelated test failures. Other platforms and the full opt-in non-SVD LAPACK suite were not rerun for this SVD-only change.
